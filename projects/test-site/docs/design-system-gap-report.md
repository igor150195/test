# Design-system gap report — test-site

Дата: 2026-10-16. Этот отчёт фиксирует пробел, обнаруженный при ретроспективной
проверке уже созданного проекта. Он не разрешает переносить его локальный CSS
в общую дизайн-систему.

## EXTEND — вкладки карьерных направлений с медиа-панелью

| Поле | Факт |
|---|---|
| Секция референса | «Направления карьеры»: Продукт, IT, Аналитика, Дизайн |
| Нужный контракт | Список tabs с доступной клавиатурной моделью, активным состоянием, связанной текстовой и image-панелью, предсказуемой mobile-перестройкой |
| Проверенные ресурсы | `design-system/components/button`, `icon-button`, `form`, `design-system/blocks/header`, `footer`, `product-card` и их документация |
| Почему не подходят | В системе нет нейтрального Tabs/Media Panel API. Button и radio из Form не документированы как tabs, а Product Card имеет товарный контракт. |
| Отсутствующий ресурс | Переиспользуемый компонент Tabs либо документированный composition pattern Tabs + Media Panel |
| Предлагаемое изменение | После отдельного согласования добавить нейтральный доступный tabs-контракт, его состояния, responsive-документацию и isolated example. |
| Затронутые файлы | Новый компонент и его docs, `components.scss`, showcase/template, Sass checks и visual QA на desktop/mobile; возможные будущие проекты с tabbed-content |
| Повторное применение | Вероятно, но не доказано одним HR-сайтом; до подтверждения не добавлять API. |
| Компромисс без изменения | Не генерировать эту секцию как «точную»; её существующая локальная реализация остаётся legacy-артефактом проекта и не является знанием для повторного использования. |

## Демонстрация поиска

Для `test-site` генератор находит `KBP-0001` как candidate процедуры полной
визуальной проверки и сопоставляет Footer/Button с действующими контрактами
дизайн-системы. Для tabs-media секции подходящего verified/approved решения
нет, поэтому корректный статус — `EXTEND`, а не самодельный компонент.
