# Чек-лист визуальной и технической приёмки сайта

## A. Техническая проверка — все пункты обязательны

- [ ] Проект собирается; результат и команда сборки записаны.
- [ ] Страницы открываются локально в браузере.
- [ ] Нет необъяснённых ошибок JavaScript в консоли.
- [ ] Нет сломанных изображений, шрифтов, иконок и CSS-ресурсов.
- [ ] Нет необъяснённых `var(--token)` без объявленного токена или предусмотренного fallback.
- [ ] Все используемые иконки есть в действующем реестре.
- [ ] Нет горизонтального overflow на ширинах 320, 375/390, 768, 1024 и 1440 px (либо заданных целевых viewport).
- [ ] Ссылки, формы и основные действия ведут к ожидаемым страницам/обработчикам; фиктивные действия не маскируются под работающие.
- [ ] Клавиатурный фокус заметен, поля имеют label, кнопки с одной иконкой имеют accessible name.
- [ ] Текст читаем при масштабировании; длинные заголовки и цены не перекрываются.

## B. Визуальная оценка — 100 баллов

Оценить каждый раздел от 0 до 5, затем умножить на вес. 0 — не выполнено, 3 — приемлемо, 5 — близко к референсу или явно лучше по ясности без потери направления.

| Критерий | Вес | Что смотреть |
|---|---:|---|
| Структура и пропорции | 25% | порядок секций, высота header/hero, ширина колонок, композиция первого экрана, визуальный центр |
| Изображения и арт-направление | 20% | правильный тип изображений, кадрирование, масштаб, визуальный контраст, отсутствие заглушек |
| Типографика | 15% | размер/вес/line-height, длина строки, переносы, разница заголовок/текст/метаданные |
| Отступы и grid | 15% | одинаковые выравнивания, повторяющийся ритм, поля страницы, gaps карточек и секций |
| Цвет и контраст | 10% | семантическая палитра, контраст текста, корректные hover/active цвета |
| Компонентные детали | 5% | радиусы, border, shadows, badges, кнопки и states |
| Адаптивность | 10% | грамотная перестройка, порядок элементов, мобильный gutter, удобство управления |

### Интерпретация

- **90–100:** готово при отсутствии критических блокеров.
- **85–89:** приемлемый результат; исправить явно заметные отклонения перед передачей.
- **70–84:** нужен ещё один цикл итерации.
- **ниже 70:** пересмотреть композицию и дизайн-решения, а не шлифовать детали.

Сумма не отменяет блокеры. Любой критический дефект из раздела A означает fail, даже если визуальный балл высокий.

## C. Очерёдность исправления дефектов

В каждом цикле выбирай максимум 3–5 проблем с наибольшим визуальным эффектом:

1. Композиция и крупные размеры/пропорции.
2. Изображение/hero и сетка.
3. Ширина текста, типографика и переносы.
4. Система расстояний и выравниваний.
5. Цвета, border, shadows и мелкие details.

Не начинать с микротюнинга теней, пока первый экран, ширина контейнера или масштаб изображения заметно отличаются от референса.

## D. Обязательные screenshot-наборы

- Desktop: целевой viewport референса, по умолчанию 1440×900.
- Mobile: 390×844 или размер исходного mobile reference.
- При длинной странице: полный page screenshot или серия одинаковых областей по прокрутке.
- Если референс — только один скриншот, проверять только реально видимую область как точное сравнение, остальное помечать как интерпретацию.

Сохранять пары с однозначными именами, например:

```text
artifacts/qa/reference-desktop.png
artifacts/qa/local-desktop-pass-1.png
artifacts/qa/local-desktop-pass-2.png
artifacts/qa/reference-mobile.png
artifacts/qa/local-mobile-pass-1.png
artifacts/qa/report.md
```

## E. Правило честности

- Не заявлять, что сравнение выполнено, если снимки не были получены/просмотрены.
- Не заявлять, что сайт точно соответствует всему референсу, если доступен только один partial screenshot.
- Разделять подтверждённые совпадения, визуальные гипотезы и недоступные для проверки элементы.
