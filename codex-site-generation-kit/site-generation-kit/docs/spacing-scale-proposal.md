# Предложение: базовая шкала отступов и layout-токены

## Задача

Добавить понятную систему отступов для новых универсальных блоков и сайтов, не ломая старые токены и не переписывая legacy-компоненты массово.

В текущей системе уже есть `--section_pd_desktop/laptop/tablet/mobile` и множество компонентных `*_gap` / `*_pd`, но нет одной ясной шкалы общего назначения. Из-за этого layout-отступы иногда используют значения, предназначенные для кнопок или радиусов.

## 1. Рекомендуемая foundation-шкала

Предлагается базовый шаг 4px и ограниченный набор значений:

| Token | Значение | Применение |
|---|---:|---|
| `--ds-space-0` | `0` | без отступа |
| `--ds-space-1` | `4px` | мелкие разделители, иконка-текст |
| `--ds-space-2` | `8px` | плотный внутренний gap |
| `--ds-space-3` | `12px` | группы мелких полей/элементов |
| `--ds-space-4` | `16px` | базовое внутреннее поле, мобильный gutter |
| `--ds-space-5` | `20px` | внутренний ритм карточек |
| `--ds-space-6` | `24px` | типовой gap сетки/групп |
| `--ds-space-8` | `32px` | отступ крупного компонента |
| `--ds-space-10` | `40px` | небольшой межсекционный интервал |
| `--ds-space-12` | `48px` | крупный внутренний интервал |
| `--ds-space-16` | `64px` | desktop section spacing |
| `--ds-space-20` | `80px` | большой вертикальный интервал |
| `--ds-space-24` | `96px` | hero / крупные display-секции |

Это предложение для новой foundation-части, а не утверждение, что каждое текущее значение нужно округлить до этой шкалы. Имеющиеся legacy-переменные следует сохранять и мигрировать только в ходе оправданных изменений.

## 2. Layout-токены должны обозначать смысл

Отступ и его назначение — не одно и то же. Кроме примитивной шкалы, новые универсальные блоки должны использовать небольшое количество семантических alias-токенов:

```css
:root {
    --ds-container-max: 1280px;
    --ds-page-gutter: var(--ds-space-6);
    --ds-grid-gap: var(--ds-space-6);
    --ds-content-gap: var(--ds-space-4);
    --ds-section-space: var(--ds-space-16);
}

@media (max-width: 767px) {
    :root {
        --ds-page-gutter: var(--ds-space-4);
        --ds-grid-gap: var(--ds-space-4);
        --ds-content-gap: var(--ds-space-3);
        --ds-section-space: var(--ds-space-10);
    }
}
```

Значения выше являются стартовым предложением и должны быть сверены с эталонными сайтами и реальными layout-примерами. `1280px` не является обязательной шириной каждого проекта: проект может осознанно переопределить `--ds-container-max` в собственной теме.

## 3. Пример применения

```css
.ds-page-container {
    width: min(100% - 2 * var(--ds-page-gutter), var(--ds-container-max));
    margin-inline: auto;
}

.ds-section {
    padding-block: var(--ds-section-space);
}

.ds-card-grid {
    display: grid;
    grid-template-columns: repeat(auto-fit, minmax(min(100%, 240px), 1fr));
    gap: var(--ds-grid-gap);
}

.ds-card__body {
    display: grid;
    gap: var(--ds-content-gap);
    padding: var(--ds-space-4);
}
```

Не обязательно принимать именно эти селекторы: важно согласовать токены и использовать их последовательно.

## 4. Что делать с текущими токенами

- `--section_pd_*` оставить совместимыми для существующих блоков; постепенно переводить новые нейтральные блоки на `--ds-section-space`.
- Компонентные `--sm_btn_gap`, `--md_btn_gap`, `--md_checkbox_gap` продолжать применять внутри соответствующих компонентов.
- Не использовать `--small_radius` как gap, даже если его значение визуально подходит. Радиус и отступ — разные смыслы.
- Не переписывать значения `new_sizes.css` массово без понимания зависимостей legacy-контрактов.
- Если значения совпадают, можно сделать alias на foundation-token в новом нейтральном API, но обратную связь менять только после проверки всех ссылок.

## 5. Как внедрять без риска

1. Добавить новый файл токенов, например `design-system/tokens/spacing.css`, и импортировать его из `design-system/scss/tokens.scss`.
2. Документировать имена и назначение в `docs/tokens.md`.
3. Обновить нейтральные блоки Header/Product Card/Footer и шаблонные layout-правила, начиная только с проекта/слоя `.ds-*`.
4. Проверить визуальные скриншоты на desktop, tablet и mobile.
5. Только после успешной проверки решать, нужны ли алиасы для отдельных legacy-токенов.

## 6. Простые правила для генератора

- Между соседними элементами одного компонента использовать content gap.
- Между карточками одной сетки — grid gap.
- Между крупными смысловыми секциями — section space.
- Слева и справа от контента использовать page gutter.
- Для ширины текста задавать разумный `max-width`/`ch`, а не растягивать текстовую колонку на весь контейнер.
- Не задавать случайные `margin-top` каждому элементу, если можно настроить единый `gap` у layout-контейнера.
- Если референс явно использует нестандартный интервал, фиксировать его как обоснованное исключение и не создавать новую глобальную переменную автоматически.
