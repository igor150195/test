# Шаблон стилей нового проекта

Новый проект хранит сгенерированные стили отдельно от ручного слоя:

```text
projects/<slug>/
├── styles/
│   ├── project.scss  # генерируемая проектная композиция
│   └── custom.scss   # изменения владельца; генератор не перезаписывает
└── css/
    ├── project.css   # результат project.scss
    └── custom.css    # результат custom.scss
```

Рядом с исходниками проекта хранятся два обязательных манифеста:
`project.json` описывает страницы, владельцев файлов, режим референса, Git
SHA генератора/дизайн-системы и `"compliance": "strict"` для нового проекта;
`assets.json` фиксирует источник, права,
локальный путь, роль и соотношение сторон каждого ресурса. Проверяйте их
командами `npm run check:project -- <slug>` и
`npm run check:assets -- <slug>`. Не объявляйте права на ресурс без
подтверждения владельца: используйте `unknown` и согласованное исключение.

## Карта Design System First

`docs/token-map.md` содержит отдельный fenced-блок `ds-section` для каждой
существенной секции. Это машиночитаемый контракт для
`npm run check:compliance -- <slug>`; JSON внутри блока отступается четырьмя
пробелами. Полная структура описана в `schemas/ds-section.schema.json`.

````md
```ds-section
{
    "id": "catalog-grid",
    "status": "COMPOSE",
    "html_selector": ".project-catalog",
    "local_selectors": [".project-catalog"],
    "local_files": ["css/project.css"],
    "ds_sources": [
        "design-system/blocks/product-card/index.md",
        "design-system/components/badge/index.md"
    ],
    "knowledge_ids": ["KBP-0002"]
}
```
````

`id` уникален в пределах карты. `html_selector` должен быть простым CSS
селектором одного HTML-элемента: `tag`, `.class`, `#id` или их комбинация.
Если его нет, проверка честно сообщает `not-verifiable`. Для `EXTEND` и
`BLOCKED` обязательны `decision` (`pending`, `approved-partial` или
`approved-extension`) и `docs/design-system-gap-report.md`. При `pending`
секция и её локальные селекторы не должны быть реализованы в проекте.

В HTML подключайте файлы в порядке: `tokens.css`, `core.css`,
`components.css`, `blocks.css`, затем (если есть тема) `css/theme.css`, затем
`css/project.css`, затем `css/custom.css`. Тема размещается после всего
собранного CSS дизайн-системы: `core.css` повторно встраивает токены и иначе
перезапишет переопределения темы.
У `custom.scss` нет права заменять отсутствующий контракт дизайн-системы:
такой пробел должен быть отмечен как `EXTEND` или `BLOCKED` до реализации.

Инициализация не перезаписывает существующий файл:

```sh
node scripts/project-styles.mjs init <slug>
node scripts/project-styles.mjs build <slug>
```

Если у нового `project.json` ещё нет поля `compliance`, `init` записывает
`"strict"`. Для старого проекта укажите `"legacy"` явно только при
согласованной миграции; новые непривязанные HTML-секции в строгом режиме
являются ошибкой `check:compliance`.

`build` компилирует `styles/project.scss` в `css/project.css`, если исходник
существует, и компилирует `styles/custom.scss` в `css/custom.css` (либо в
явно переданный выходной путь), только если этот исходник был заранее создан
через `init`. Команда не создаёт `custom.scss` сама.

Для S3 используйте в проектных SCSS только `@import`: `@use`, `@forward` и
`sass:*` несовместимы со scssphp; предупреждения Dart Sass об `@import` и
`slash-div` не исправляются.

Каждый CSS-файл, записанный `build`, получает заголовок
`/* generated by project-styles */`. Если выходной файл уже существует без
этого заголовка, запись останавливается, чтобы не потерять ручной или legacy
CSS. Допускается заменить пустой файл или файл только с комментариями и
`@charset`; для осознанной замены любого другого файла используйте `--force`.

Для существующего проекта, где `css/custom.css` уже является основным
генерируемым стилем, используйте другой выходной путь, например
`css/custom-overrides.css`, и подключайте его последним. Не мигрируйте и не
очищайте прежний файл без согласования с владельцем.

Для переносимой поставки сначала соберите общую дизайн-систему, затем выполните
`npm run site:build -- <slug>`. Команда создаёт `projects/<slug>/dist/`,
объединяет разрешённые таблицы стилей в порядке токенов, core, components,
blocks и проектных файлов, копирует спрайт и заменяет только ожидаемые ссылки
на общие CSS. Она откажется от неожиданной разметки, несобранного корневого
`dist/` или отсутствующего локального ресурса. Результат не содержит времени
сборки и воспроизводим при неизменных исходниках.
