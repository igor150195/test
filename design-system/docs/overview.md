# Текущий публичный API дизайн-системы

## Статус документа

Документ фиксирует фактическое состояние репозитория до исправления ошибок, рефакторинга и настройки сборки. Под «публичным API» здесь понимаются доступные потребителю CSS custom properties, SCSS-миксины и SVG `view` ID. Наличие файла в репозитории не означает, что его API уже является универсальным или платформонезависимым.

Сборка, демонстрационный проект и реальные места подключения в репозитории отсутствуют. Поэтому порядок импорта, поддерживаемая HTML-разметка и поведение части API не подтверждены работающим потребителем.

## Текущая структура

design-system/

│   ├── footer/                 # пустой каталог
│   └── header/                 # пустой каталог

├── scss/

│   ├── legacy-platform.scss   # полный текущий набор
│   ├── check.scss             # smoke-check всех миксинов
│   └── tokens.scss            # runtime token layer
├── sets/
│   └── 1/
│       └── new.sprite.view.svg # SVG view-sprite, 138 view ID
└── tokens/
    ├── new_colors.css          # 184 объявления токенов
    ├── fonts.css               # системные fallback-стеки --font1/--font2
    ├── icons.css               # URL-реестр всех текущих SVG view ID

Каталог `projects/` находится в корне репозитория и сейчас пуст. В корне добавлены `package.json` и `package-lock.json` с минимальной Dart Sass сборкой. Тестовые HTML-страницы по-прежнему отсутствуют. Команды и границы проверки описаны в [build.md](build.md).

## Фактические слои

### Design tokens

Файлы `tokens/new_colors.css`, `tokens/fonts.css`, `tokens/new_sizes.css` и `tokens/icons.css` объявляют глобальные переменные в `:root`. Цветовой файл содержит базовые и семантические цвета; `fonts.css` задаёт системные fallback-стеки; размерный файл содержит одновременно foundation-токены и большое число компонентных токенов; `icons.css` связывает существующие SVG `view` ID с URL-переменными.

Размерный файл зависит от цветового: многие его значения ссылаются на `--primary`, `--on_bg_main`, `--bg_main` и другие переменные из `new_colors.css`. Зависимости `--font1`, `--font2` и URL для имеющихся SVG ID теперь обеспечиваются новыми token-файлами. Подробности об оставшихся отсутствующих ресурсах перечислены в [tokens.md](tokens.md).

### SCSS mixins

Каталог `mixins/` содержит функции генерации размеров, визуальных состояний и вложенных селекторов. `scss/core.scss` и `scss/legacy-platform.scss` задают минимальные проверочные entrypoint на legacy `@import`; миграция на `@use`/`@forward` ещё не выполнялась.

Часть миксинов нейтральна и задаёт свойства только текущему селектору. Другая часть генерирует селекторы `.gr-*`, `.remodal*`, `.shop2-*`, `.tpl-rating`, `.js-selected` либо предполагает конкретную вложенность DOM. Полный контракт зафиксирован в [mixins.md](mixins.md).

### Icons

`sets/1/new.sprite.view.svg` — один SVG-документ размером `500 × 240` с `viewBox="0 0 500 240"`. Он содержит 138 элементов `<view>` и 138 вложенных `<svg>`. ID элементов `<view>` являются фактическим публичным идентификатором иконки.

В исходниках иконки используются как CSS mask через переменные вида `--icon_cross_md`. `tokens/icons.css` содержит URL-реестр для всех существующих SVG-фрагментов. Реестр ID приведён в [icons.md](icons.md).

### Components и blocks

Реализованных самостоятельных компонентов и блоков в репозитории нет. Каталоги `components/header` и `components/footer` пусты. Наличие компонентных токенов или миксина не подтверждает наличие самостоятельного компонента: HTML, базовые стили и интерактивное поведение не представлены.

### Platform integrations

Отдельного слоя адаптеров пока нет. Платформенные зависимости находятся непосредственно в миксинах:

- Remodal: `.remodal-close-btn`, `.remodal__title`, `.remodal--title-margin`;
- Shop2: `.shop2-product-discount-desc`;
- `gr-*`: `.gr-mask-icon`, `.gr-multiselect__*`, `.gr-color-picker__*`, `.gr-actions__*` и другие;
- другие legacy-контракты: `.tpl-rating`, `.product-amount__*`, `.price-old`, `.price-current`, `.promo-action__*`, `.js-selected`.

Происхождение и обязательность всех `gr-*` классов по текущему репозиторию не подтверждены.

## Универсальный API и платформенные решения

К универсальному API-кандидату относятся контракты, которые не генерируют известные платформенные классы и используют общие CSS-свойства: цветовые токены, типографические токены, `heading_type`, `text_type`, `icon`, простые размерные миксины. Статус «кандидат» не означает готовность к использованию: сборка и реальные потребители отсутствуют.

Платформенными считаются контракты с прямыми селекторами Shop2, Remodal, `gr-*`, `.tpl-rating` и `.js-selected`. Их нельзя считать универсальными только потому, что значения вынесены в токены.

Миксины, которые предполагают конкретную, но не идентифицированную как внешняя платформа DOM-структуру (`ul > li`, `input + span`, `.product-amount__*`), помечены как «пока не классифицирован».

## Существующие зависимости

```text
new_colors.css
       ↓
fonts.css ─────────→ --font1 / --font2
icons.css ─────────→ существующие SVG URL custom properties
new_sizes.css ─────→ отсутствующие checkbox/rating-lg resources
       ↓
SCSS mixins ───────→ ожидаемая DOM-структура и внешние классы
       ↓
готовый CSS         → проверяется entrypoint-файлами в design-system/scss

new.sprite.view.svg → icons.css URL custom properties
```

`_popup.scss` дополнительно вызывает `icon_button`, `icon` и `popup_title`, но сам не импортирует их. Проверочный `legacy-platform.scss` подключает эти зависимости раньше `_popup.scss`. Исторический порядок во внешних потребителях не подтверждён.

## Ограничения этой фиксации

- Нет возможности подтвердить, какие миксины реально используются.
- Нет возможности подтвердить доступные браузеры и поддержку внешнего SVG fragment view в целевом окружении.
- Нет исходников JavaScript, задающих состояния `.js-selected` или управляющих Remodal/`gr-*` компонентами.
- Нет HTML-примеров, поэтому предполагаемая структура описана только там, где она явно следует из вложенных SCSS-селекторов.
- Документы не вводят новые имена и не изменяют существующие контракты.
