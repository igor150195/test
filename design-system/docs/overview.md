# Текущий публичный API дизайн-системы

## Статус и границы

Этот документ описывает фактическую структуру репозитория на этапе
стабилизации. Публичным API считаются CSS custom properties из token-слоя,
задокументированные HTML-контракты компонентов и блоков, нейтральные
SCSS-миксины с подтверждённой применимостью и ID текущего SVG-спрайта.
Наличие legacy-миксина не делает его платформонезависимым API.

Новые сайты используют дизайн-систему через собранные стили из `dist/css/` и
создают индивидуальные стили внутри своего каталога `projects/<slug>/`. Общие
токены, компоненты и блоки не изменяются ради особенностей одного проекта.
Для сайта по URL или скриншоту обязательна карта `REUSE` / `COMPOSE` /
`EXTEND` / `BLOCKED` из [Design System First](generation/design-system-first.md).

## Структура

```text
design-system/
├── tokens/                    # CSS-переменные цветов, размеров, шрифтов, иконок и spacing
├── core/                      # base, a11y и typography SCSS-модули
├── components/                # 8 нейтральных компонентов с index.md-контрактами
├── blocks/                    # Header, Product Card и Footer
├── adapters/                  # legacy, Shop2 и Remodal-адаптеры
├── mixins/                    # существующие SCSS-миксины, включая legacy-зависимые
├── sets/1/new.sprite.view.svg # SVG view-sprite
├── scss/                      # Sass entrypoint’ы
├── templates/                 # home.html, shop.html и шаблон проектных стилей
└── docs/                      # API, сборка и документация генерации

projects/
├── fashion-store/
├── house-store/
└── test-site/

dist/css/                      # генерируемый CSS, не исходники
scripts/                       # проверки и безопасная сборка проектных стилей
```

## Слои и порядок подключения

1. `tokens.css` — `new_colors.css`, `fonts.css`, `new_sizes.css`,
   `spacing.css`, `icons.css`.
2. `core.css` — базовые правила, доступность, нейтральная типографика и
   Core-кандидаты из миксинов.
3. `components.css` — Button, Icon, Icon Button, Form, Rating, Price,
   Counter и Badge.
4. `blocks.css` — Product Card, Header и Footer.
5. `legacy-platform.css` — только при необходимости старых платформенных
   контрактов; нейтральный проект его не подключает.
6. Стили проекта: `css/project.css`, затем сохранённый ручной слой
   `css/custom.css` или явно названный override-файл.

Полная команда и ограничения приведены в [build.md](build.md). `check.scss`
является Sass smoke fixture, а не runtime-стилем страницы.

## Design tokens и icons

Все runtime-токены объявляются в `:root`. Цветовые и размерные токены имеют
исторические имена; их нельзя массово переименовывать без миграции.
`spacing.css` добавляет совместимые `--ds-space-*` и семантические layout
значения. `fonts.css` задаёт безопасные fallback-стеки `--font1` и `--font2`.

`icons.css` сопоставляет CSS-переменные с фрагментами
`sets/1/new.sprite.view.svg`. Список ID, размеры и ограничения внешнего SVG
mask — в [icons.md](icons.md); известные отсутствующие токены — в
[tokens.md](tokens.md).

## Компоненты и blocks

Нейтральные компоненты подключаются из `components.css`; их чистые HTML
контракты находятся в соответствующих `index.md`:

- `button`, `icon`, `icon-button`;
- `form` (input, select, textarea, checkbox, radio);
- `rating`, `price`, `counter`, `badge`.

Составные блоки подключаются из `blocks.css`: `header`, `product-card`,
`footer`. Шаблоны `home.html` и `shop.html` показывают композицию этих
контрактов, но не являются требованием копировать их визуальный стиль.

Компонентные каталоги `components/header` и `components/footer` отсутствуют:
Header и Footer являются именно blocks, а не components.

## Core, mixins и adapters

`core.scss` не содержит привязок к Shop2 или Remodal. Платформенные селекторы
изолированы в `adapters/legacy`, `adapters/shop2`, `adapters/remodal` и входят
только в `legacy-platform.scss`.

Миксины остаются legacy `@import` API. Некоторые генерируют `gr-*`, Shop2,
Remodal, `.tpl-rating`, `.js-selected` или ожидают жёсткую DOM-вложенность;
их нельзя применять как нейтральные компоненты без проверки. Аргументы,
значения по умолчанию и статус каждого миксина перечислены в
[mixins.md](mixins.md).

## Проекты и ручные изменения

Проект сначала получает `styles/project.scss` (генерируемая композиция) и
`styles/custom.scss` (ручной слой владельца). Инициализация создаёт
`custom.scss` один раз; повторный запуск его не меняет. Сборщик проектных
стилей записывает только CSS с маркером `/* generated by project-styles */` и
не заменяет нераспознанный CSS без явного `--force`. Подробный контракт — в
[templates/project/README.md](../templates/project/README.md) и
[generator-guide.md](generator-guide.md).

В `projects/` есть реальные примеры и QA-артефакты. Артефакты PNG не являются
частью публичного API и могут быть игнорированы Git.

## Проверки и известные ограничения

- `npm run build` и `npm run check:sass` проверяют Sass, но не гарантируют
  визуальное сходство с референсом.
- `npm run test:project-styles` проверяет сохранность ручного SCSS и защиту
  вывода CSS.
- `npm run check:docs` проверяет локальные Markdown-ссылки и конфликтующие
  копии инструкций.
- `npm run check:tokens` фиксирует конфликтные/неопределённые токены и
  `.ds-*` классы из HTML относительно built CSS. Известные legacy-дефекты
  выводятся предупреждениями до отдельного согласованного исправления.
- Проверку рендера и адаптивности выполняет
  `.agents/skills/visual-qa/SKILL.md`, если доступен браузер.

Известны конфликт `--toggle_title_icon_h`, три отсутствующих икон-токена и
неоформленный контракт `.ds-footer__column`. Они документированы, но не
исправляются этим обзором.
